1. INTRODUCTION

What is This Framework?

RAG Framework = Retrieval-Augmented Generation Framework
  • **Multi-tenant:** Multiple teams share infrastructure but have isolated data
  • **Retrieval-only:** Pure FAQ search system (no LLM, no answer generation)
  • **Enterprise-grade:** Type-safe, scalable, well-documented
  • **Local & Private:** All processing happens on-device (no external APIs)

    • Core Problem Solved

    Teams need to: 1. Store FAQ documents 2. Search semantically (by meaning, not keywords) 3. Get relevant results ranked by relevance 4. Keep data isolated per team 5. Use simple REST API or Python SDK

    Solution Philosophy

    
Traditional Approach (Bad):
User Question
    ↓
Simple Keyword Search (many false negatives)
    ↓
Irrelevant Results

RAG Framework Approach (Good):
User Question
    ↓
Convert to Vector (semantic meaning captured)
    ↓
Find Similar Vectors (fast similarity search)
    ↓
Rank by Relevance (best matches first)
    ↓
Relevant Results

    How It Works (Under the Hood)

    
Input Text: "How do I reset my password?"
    │
    ├─ Tokenization
    │  ↓
    │  ["how", "do", "i", "reset", "my", "password", "?"]
    │
    ├─ Token Embedding (learned lookup table)
    │  ↓
    │  [[0.1, 0.2, ...], [0.3, 0.4, ...], ...]
    │
    ├─ Transformer Layers (6 layers in MiniLM)
    │  ↓
    │  [Process through attention mechanisms to understand relationships]
    │
    ├─ Mean Pooling (average all token embeddings)
    │  ↓
    │  [Average vector across all tokens]
    │
    ├─ L2 Normalization (crucial for cosine similarity)
    │  ↓
    │  Magnitude = sqrt(sum of squares) = 1.0
    │
    └─ Output: Vector of 384 floats
       [0.123, 0.456, 0.789, ..., 0.999]
       (all values between -1 and 1)

Cosine Similarity (how we compare vectors):
═══════════════════════════════════════════════════════
Query Vector Q:     [0.1, 0.2, 0.3, ...]
Document Vector D:  [0.1, 0.2, 0.3, ...]

Similarity = (Q · D) / (|Q| × |D|)
           = Dot product / (magnitude Q × magnitude D)
           = Between 0 and 1 (1.0 = identical meaning)
           
Example:
Q = [1, 0]
D = [1, 0]
Similarity = 1/1 × 1 = 1.0 ✓ (identical)

Q = [1, 0]
D = [0, 1]
Similarity = 0/1 × 1 = 0.0 (completely different)

Q = [1, 0]
D = [0.7, 0.7]
Similarity = 0.7/sqrt(1) × sqrt(0.98) = 0.69 (similar)

   ┌──────────────────────────────────────┐

            │
            ├─ Find closest vectors using HNSW index
            │  (not brute-force, uses smart indexing)
            ├─ Return top-n results with distances
            └─ Convert distances to similarities
               (similarity = 1 - distance)

3. DELETE DOCUMENTS:
   ┌──────────────────────────────────────┐
   │ delete(ids)                          │
   └────────┬─────────────────────────────┘
            │
            └─ Remove vectors and metadata
               (important for GDPR compliance)

═════════════════════════════════════════════════════════

Team 1 searches "password" → Only finds team_1_documents

- Each collection has separate vector index
- Search operation specifies collection name
- No cross-collection queries possible
- Perfect isolation guaranteed

from sentence_transformers import SentenceTransformer
from typing import List
import logging
from src.config.settings import settings
from src.domain.exceptions import EmbeddingError

logger = logging.getLogger(__name__)

class EmbeddingService:
    """
    Local text-to-vector conversion service.
    
    Uses sentence-transformers/all-MiniLM-L6-v2 model:
    - 384-dimensional output vectors
    - Pre-trained on 215M sentence pairs
    - Optimized for semantic similarity
    """

    def __init__(self, model_name: str = None):
        """
        Initialize the embedding service.
        
        Args:
            model_name: HuggingFace model ID
                       Defaults to: sentence-transformers/all-MiniLM-L6-v2
        
        Process:
        1. Get model name from parameter or settings
        2. Log the model being loaded
        3. Download model from HuggingFace (if not cached)
        4. Load into memory
        5. Check it loaded correctly
        
        Why check at init?
        - Fail fast if model not available
        - Don't waste time discovering issues at query time
        """
        self.model_name = model_name or settings.embedding_model
        self.vector_dimension = settings.vector_dimension

        logger.info(f"Loading embedding model: {self.model_name}")

        try:
            # Load model from HuggingFace or local cache
            # First time: downloads ~80MB
            # Subsequent times: uses cached copy
            self._model = SentenceTransformer(self.model_name)
            
            logger.info(
                f"✓ Embedding model loaded. "
                f"Dimension: {self.vector_dimension}"
            )
        except Exception as e:
            # Log error and raise custom exception
            logger.error(f"Failed to load embedding model: {e}")
            raise EmbeddingError(
                f"Could not load model {self.model_name}: {str(e)}"
            )

    def embed_text(self, text: str) -> List[float]:
        """
        Embed a single piece of text.
        
        Args:
            text: Text to embed (e.g., "How to reset password?")
        
        Returns:
            Vector as list of floats: [0.123, 0.456, ..., 0.789]
            (384 elements, normalized to unit length)
        
        Process:
        1. Pass text to model.encode()
        2. Model tokenizes (splits into subwords)
        3. Transformer layers process tokens
        4. Mean pooling averages token embeddings
        5. L2 normalization makes magnitude = 1.0
        6. Convert numpy array to list
        
        Why normalize?
        - Makes cosine similarity meaningful
        - All vectors on unit sphere
        - Comparison metric becomes: dot_product
        
        Example:
            vector = service.embed_text("reset password")
            len(vector) == 384  # True
            sum(v**2 for v in vector) ≈ 1.0  # L2 norm
        """
        try:
            # Encode text to vector
            # normalize_embeddings=True applies L2 norm
            vector = self._model.encode(
                text,
                normalize_embeddings=True  # L2 norm
            )
            
            # Convert numpy array to Python list
            # (JSON-serializable, human-readable)
            return vector.tolist()
            
        except Exception as e:
            logger.error(f"Embedding error for text: {text[:50]}...")
            raise EmbeddingError(f"Failed to embed text: {str(e)}")

    def embed_texts(self, texts: List[str]) -> List[List[float]]:
        """
        Embed multiple texts efficiently (batch processing).
        
        Args:
            texts: List of texts to embed
        
        Returns:
            List of vectors: [[0.1, 0.2, ...], [0.3, 0.4, ...], ...]
        
        Why batch processing?
        - GPU/CPU can process multiple texts at once
        - 10x faster than embedding one-by-one
        - Better memory utilization
        
        Process:
        1. Check list not empty (avoid errors)
        2. Call model.encode() with batch_size=32
        3. Model automatically batches efficiently
        4. Convert all results to lists
        
        Batch size logic:
        - batch_size=32: Good balance for most hardware
        - Smaller batch_size: Uses less memory
        - Larger batch_size: Faster but needs more RAM
        
        Example:
            texts = ["How to reset?", "Create account?", "Enable 2FA?"]
            vectors = service.embed_texts(texts)
            len(vectors) == 3
            len(vectors[0]) == 384
        """
        if not texts:
            logger.warning("embed_texts called with empty list")
            return []

        try:
            logger.debug(f"Embedding {len(texts)} texts")

            # Batch encode (much faster)
            vectors = self._model.encode(
                texts,
                normalize_embeddings=True,
                batch_size=32,  # Process 32 at a time
                show_progress_bar=False
            )

            return vectors.tolist()
            
        except Exception as e:
            logger.error(f"Batch embedding error: {e}")
            raise EmbeddingError(f"Failed to embed batch: {str(e)}")

    def get_dimension(self) -> int:
        """
        Get vector dimension.
        
        Returns:
            384 (for all-MiniLM-L6-v2)
        
        Why needed?
        - ChromaDB needs to know dimension upfront
        - Different models have different dimensions:
          • all-MiniLM-L6-v2: 384
          • all-mpnet-base-v2: 768
          • OpenAI text-embedding-3: 1536
        - Used for validation
        """
        return self.vector_dimension

    def health_check(self) -> bool:
        """
        Quick health check (can we embed?).
        
        Returns:
            True if model works, False otherwise
        
        Process:
        1. Try to embed test word
        2. Check output dimension is correct
        3. Return success/failure
        
        Used for:
        - Monitoring (liveness probe)
        - Graceful degradation
        - Debugging
        """
        try:
            test_vector = self.embed_text("test")
            return len(test_vector) == self.vector_dimension
        except Exception as e:
            logger.error(f"Health check failed: {e}")
            return False

import chromadb
from chromadb.config import Settings
from typing import List, Dict, Optional, Tuple
import logging
from src.config.settings import settings
from src.domain.models import Document
from src.domain.exceptions import VectorStoreError

logger = logging.getLogger(__name__)

class ChromaDBVectorStore:
    """
    Vector storage using ChromaDB with team-level isolation.
    
    Key Features:
    - One ChromaDB instance handles all teams
    - Each team has separate collection
    - Data persists to disk
    - Team isolation enforced at collection level
    - kNN search optimized with HNSW index
    """

    def __init__(self, persist_dir: str = None):
        """
        Initialize ChromaDB with persistent storage.
        
        Args:
            persist_dir: Directory to store vectors
                        Defaults to ./chroma_data
        
        Process:
        1. Set persist directory path
        2. Configure ChromaDB settings
        3. Create Client with DuckDB backend
        4. Test initialization
        
        Why DuckDB + Parquet?
        - DuckDB: Fast SQL database engine
        - Parquet: Columnar format (efficient for vectors)
        - Together: Fast, persistent vector storage
        """
        self.persist_dir = persist_dir or settings.chroma_persist_dir

        # Configure ChromaDB for persistence
        chroma_settings = Settings(
            chroma_db_impl="duckdb+parquet",  # Backend: DuckDB + Parquet
            persist_directory=self.persist_dir,  # Where to save
            anonymized_telemetry=False  # Disable tracking
        )

        try:
            logger.info(f"Initializing ChromaDB at: {self.persist_dir}")
            self.client = chromadb.Client(chroma_settings)
            logger.info("✓ ChromaDB initialized")
        except Exception as e:
            logger.error(f"Failed to initialize ChromaDB: {e}")
            raise VectorStoreError(f"ChromaDB initialization failed: {e}")

    def _get_collection_name(self, team_id: str) -> str:
        """
        Generate collection name from team_id.
        
        Args:
            team_id: Team identifier (e.g., "team-1")
        
        Returns:
            Collection name (e.g., "team_1_documents")
        
        Why separate method?
        - Consistency: Same naming everywhere
        - Easy to change scheme later
        - Clear mapping between team_id and collection
        
        Naming constraint:
        - ChromaDB collections: alphanumeric + underscore
        - Input: "team-1" (has hyphen)
        - Output: "team_1_documents" (hyphen → underscore)
        """
        safe_team_id = team_id.replace("-", "_")
        return f"{safe_team_id}_documents"

    def _get_or_create_collection(self, team_id: str):
        """
        Get existing collection or create new one.
        
        Args:
            team_id: Team identifier
        
        Returns:
            ChromaDB collection object
        
        Process:
        1. Generate collection name from team_id
        2. Call client.get_or_create_collection()
        3. If exists: return existing
        4. If not: create with team_id in metadata
        
        Why metadata?
        - Track which team owns collection
        - Useful for debugging, auditing
        - Not used for retrieval (just informational)
        
        Why idempotent?
        - Safe to call multiple times
        - First call: creates collection
        - Subsequent calls: return existing
        - No errors on re-initialization
        """
        collection_name = self._get_collection_name(team_id)

        try:
            collection = self.client.get_or_create_collection(
                name=collection_name,
                metadata={"team_id": team_id},  # Store team context
                embedding_function=None  # We provide embeddings
            )
            return collection
        except Exception as e:
            logger.error(f"Failed to get/create collection for {team_id}: {e}")
            raise VectorStoreError(f"Collection error for {team_id}: {e}")

    def add_documents(
        self,
        team_id: str,
        documents: List[Document]
    ) -> int:
        """
        Add documents (with embeddings) to team's collection.
        
        Args:
            team_id: Team identifier
            documents: List of Document objects (with embeddings)
        
        Returns:
            Number of documents added
        
        Process:
        1. Validate all docs have embeddings
        2. Get or create team's collection
        3. Extract data in ChromaDB format:
           - ids: document IDs
           - embeddings: vectors (384-dim)
           - documents: text content
           - metadatas: category, keywords, entities
        4. Call collection.add()
        5. ChromaDB indexes vectors automatically (HNSW)
        
        Why validate embeddings?
        - Embeddings are required for retrieval
        - Better to fail here than later in search
        - Saves time debugging query failures
        
        HNSW Indexing:
        - Hierarchical Navigable Small World
        - Graph-based indexing for fast kNN
        - Trade-off: Memory for speed
        - Makes 100k doc search instant
        
        Example:
            docs = [
                Document(
                    id="doc-1",
                    content="Reset password...",
                    embedding=[0.1, 0.2, ..., 0.9],
                    category="account",
                    keywords=["password", "reset"]
                )
            ]
            count = store.add_documents("team-1", docs)
            # Returns: 1
        """
        if not documents:
            logger.warning(f"add_documents called with no docs for {team_id}")
            return 0

        # Check all have embeddings
        for doc in documents:
            if not doc.embedding:
                raise VectorStoreError(
                    f"Document {doc.id} has no embedding"
                )

        try:
            collection = self._get_or_create_collection(team_id)

            logger.info(f"Adding {len(documents)} documents to {team_id}")

            # Prepare data for ChromaDB format
            ids = [doc.id for doc in documents]
            embeddings = [doc.embedding for doc in documents]
            documents_text = [doc.content for doc in documents]
            metadatas = [
                {
                    "faq_id": doc.faq_id if hasattr(doc, 'faq_id') else '',
                    "category": doc.category,
                    "keywords": ",".join(doc.keywords),
                    "entities": ",".join(doc.entities),
                    "team_id": team_id
                }
                for doc in documents
            ]

            # Add to ChromaDB
            collection.add(
                ids=ids,
                embeddings=embeddings,
                documents=documents_text,
                metadatas=metadatas
            )

            logger.info(f"✓ Added {len(documents)} docs to {team_id}")
            return len(documents)

        except Exception as e:
            logger.error(f"Failed to add documents for {team_id}: {e}")
            raise VectorStoreError(f"Failed to add documents: {e}")

    def search(
        self,
        team_id: str,
        query_vector: List[float],
        top_k: int = 5,
        filters: Optional[Dict] = None
    ) -> List[Tuple[str, float, Dict]]:
        """
        Search for similar documents using vector.
        
        Args:
            team_id: Team identifier (ensures isolation)
            query_vector: Query embedding (384-dim, normalized)
            top_k: Number of results to return (default 5)
            filters: Optional metadata filters (not used yet)
        
        Returns:
            List of tuples: [(doc_id, similarity_score, metadata), ...]
            Sorted by similarity_score (descending)
        
        Process:
        1. Get team's collection
        2. Call collection.query() with vector
        3. ChromaDB uses HNSW index to find closest vectors
        4. Get results with distances
        5. Convert distances to similarities
           • Cosine distance: 0 to 2
           • Similarity = 1 - distance
           • Result: 0 to 1 (1.0 = identical)
        6. Return as tuples
        
        Why tuple format?
        - Minimal: Only essential info
        - Flexible: Caller decides what to do
        - Efficient: No unnecessary data transfer
        
        Distance vs Similarity:
        - ChromaDB returns distances
        - Distance = 1 - similarity (cosine)
        - Example:
          • Query and doc identical: distance=0, similarity=1.0
          • Completely different: distance=2, similarity=-1 (capped to 0)
          • Somewhat similar: distance=0.3, similarity=0.7
        
        Team Isolation:
        - Search only happens in team_id collection
        - No cross-team results possible
        - Guaranteed data privacy
        
        Example:
            query_vector = [0.1, 0.2, ..., 0.9]  # 384 dims
            results = store.search("team-1", query_vector, top_k=5)
            # Returns:
            # [
            #   ("doc-1", 0.92, {"category": "account", ...}),
            #   ("doc-2", 0.85, {"category": "account", ...}),
            #   ...
            # ]
        """
        try:
            collection = self._get_or_create_collection(team_id)

            # Query ChromaDB for similar vectors
            results = collection.query(
                query_embeddings=[query_vector],
                n_results=top_k,
                where=filters  # Optional metadata filtering
            )

            # Parse ChromaDB results
            # ChromaDB returns nested lists
            doc_ids = results["ids"][0]  # First (only) query
            distances = results["distances"][0]
            metadatas = results["metadatas"][0]

            # Convert distance to similarity
            # (1 - distance) for cosine
            similarities = [1 - d for d in distances]

            # Combine into tuples
            return list(zip(doc_ids, similarities, metadatas))

        except Exception as e:
            logger.error(f"Search failed for {team_id}: {e}")
            raise VectorStoreError(f"Search failed: {e}")

    def delete_document(self, team_id: str, doc_id: str) -> bool:
        """
        Delete a document from team's collection.
        
        Args:
            team_id: Team identifier
            doc_id: Document ID to delete
        
        Returns:
            True if successful
        
        Use Cases:
        - GDPR "right to be forgotten"
        - Remove outdated FAQs
        - Data cleanup
        
        Important:
        - Idempotent: Safe to call multiple times
        - No error if doc doesn't exist
        - Actually removes from ChromaDB (persisted immediately)
        """
        try:
            collection = self._get_or_create_collection(team_id)
            collection.delete(ids=[doc_id])
            logger.info(f"Deleted {doc_id} from {team_id}")
            return True
        except Exception as e:
            logger.error(f"Failed to delete {doc_id}: {e}")
            return False

    def get_stats(self, team_id: str) -> Dict:
        """
        Get statistics for team's collection.
        
        Args:
            team_id: Team identifier
        
        Returns:
            Stats dictionary:
            {
                "team_id": "team-1",
                "collection_name": "team_1_documents",
                "document_count": 1523,
                "vector_dimension": 384
            }
        
        Use Cases:
        - Monitoring: Know what's in each collection
        - Debugging: Verify data was stored
        - Analytics: Track usage per team
        - Capacity planning: Know collection sizes
        """
        try:
            collection = self._get_or_create_collection(team_id)
            count = collection.count()

            return {
                "team_id": team_id,
                "collection_name": self._get_collection_name(team_id),
                "document_count": count,
                "vector_dimension": settings.vector_dimension
            }
        except Exception as e:
            logger.error(f"Failed to get stats for {team_id}: {e}")
            raise VectorStoreError(f"Stats retrieval failed: {e}")

    def health_check(self) -> bool:
        """
        Check if ChromaDB is healthy.
        
        Returns:
            True if working, False otherwise
        
        Used for:
        - Kubernetes liveness probes
        - Monitoring dashboards
        - Request validation (fail fast)
        
        Process:
        - Try to list all collections
        - If succeeds: healthy
        - If fails: unhealthy
        """
        try:
            self.client.list_collections()
            return True
        except Exception as e:
            logger.error(f"ChromaDB health check failed: {e}")
            return False
